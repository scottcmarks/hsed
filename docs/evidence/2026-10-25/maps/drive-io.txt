##### drive-io

SUMMARY:
The real-drive I/O path is Drive Trust Alliance's sedutil (C++), checked out at ~/preboot/DTA/sedutil (detached HEAD 136389c on origin/develop, v1.49.1) plus Scott/Jackie's proprietary macOS kext at ~/preboot/DTA/macos-driver (detached HEAD 8bf2635 on develop). sedutil is layered: DtaDev (SSC-level verbs: DtaDevOpal/Enterprise/Pyrite/Generic) -> DtaSession (HSN/TSN, method-status parsing) -> DtaCommand/DtaResponse (token stream + ComPacket/Packet/SubPacket headers in 16 KiB-aligned buffers, MAX 61440 / MIN 2048 bytes) -> DtaDrive (protocol subclass: Scsi, Ata/Sata via SAT, Nvme, BlockStorageDevice stub) -> DtaOS singleton (per-OS PerformSCSICommand / PerformATACommand / PerformNVMeCommand). The single "serialized ComPacket" boundary is the pure virtual `DtaDrive::sendCmd(ATACOMMAND cmd, uint8_t protocol, uint16_t comID, void *buffer, unsigned bufferlen)`: `buffer` is the raw IF-SEND/IF-RECV payload, lengths are multiples of 512, and `DtaDevOpal::exec` drives it as one TRUSTED_SEND followed by a 25 ms-polled TRUSTED_RECEIVE loop while ComPacket outstandingData!=0 && minTransfer==0. ComIDs are static (base ComID from Level 0 Discovery; no GET_COMID), TPerReset is IF-SEND protocol 0x02 ComID 0x0004, and Level 0 Discovery is IF-RECV protocol 0x01 ComID 0x0001 into a 2048-byte buffer.

On macOS the only working transport is the BrightPlazaTPer kext (com.brightplaza.BrightPlazaTPer 2.0.5/625, loaded on this Mac; SIP disabled; macOS 27.0.1 arm64; Xcode 27). It subclasses IOSCSIPeripheralDeviceType00, matches IOSCSIPeripheralDeviceNub PDT 0 with a raised probe score, runs its own Level 0 Discovery at attach (SCSI SECURITY PROTOCOL IN A2h, or SAT ATA PASS-THROUGH(12) A1h wrapping TRUSTED RECEIVE 5Ch) and publishes the parsed DTA_DEVICE_INFO as the IORegistry property "DTA Device Info". User space talks to it through SEDKernelInterface.framework, a plain C ABI (OpenUserClient, DriverPerformSCSICommand, TPerUpdate, CloseUserClient, findBSDName, findParent, ...; symbols verified exported), which marshals a 12-byte CDB + page-aligned user buffer through IOConnectCallScalarMethod into the kext's copyin/copyout + IOSCSIPrimaryCommandsDevice::SendCommand (10 s timeout). The kext whitelists only INQUIRY, REQUEST SENSE, A2h, B5h and A1h with ATA 5Ch/5Eh/ECh, requires admin privilege and exclusive open, and does not return sense data to user space. NVMe Security Send/Receive and "ATA via HD" are unimplemented on macOS (both return DTAERROR_FAILURE), so only USB-bridged SEDs (SAT or UAS/SCSI) are reachable; internal NVMe/SATA are not. A Realtek RTL9210 USB-NVMe bridge holding a Samsung 970 EVO Plus (TCG Options word = 0, attached only because of the tperOverrides "tryUnjustifiedLevel0Discovery" quirk) is attached right now as /dev/disk6 with "TPer Interface Type"="SAT".

For a Haskell host, the thinnest realistic call is direct FFI to SEDKernelInterface.framework's C functions (plus a handful of IOKit calls), building the 12-byte CDB in Haskell and handing a page-aligned ByteString; the portable alternative is a ~3-function C shim (getDtaDrive / sendCmd / discovery0) over the existing DtaDrive classes linked against sedutil.framework (installed in /Library/Frameworks) or the Common/*.cpp sources, which sedutil's own TODO.txt already proposes ("libsed ... void * handles ... Python or Haskell"). The sedutil-cli subprocess route is unsuitable for a serialized command/response stream: it exposes only high-level verbs (--scan, --query --json, --rawCmd, --TCGReset) and no raw IF-SEND/IF-RECV passthrough. The macOS build is Xcode-only (no autotools path), driven by macos/CI/make_tools -> xcodebuild -workspace SEDTools.xcworkspace -scheme 'All targets (SEDUtilities project)'; sedutil-cli links /Library/Frameworks/SEDKernelInterface.framework by absolute path, so the driver's framework must be built/installed first. `xcodebuild -list` succeeds for both workspaces today; the last actual build products are from 2024-05-07 (14.4 SDK) and no build was attempted in this sweep. ~/CLI.BrightPlaza is a stale 2023-12-22 snapshot of the CLI Xcode tree (tracked directly in the home repo, including plaintext private keys), not what the CI builds.

RISKS:
  - macOS reach is limited to USB-bridged SEDs through the kext: DtaMacOS::PerformNVMeCommand and PerformATACommand_via_HD both return DTAERROR_FAILURE, so internal Apple NVMe and direct SATA are not testable on a Mac; Linux (errol/x86) is needed for NVMe ioctl and SG_IO paths.
  - The kext is a legacy IOKit kext (deployment target 11.3, OSBundleRequired Local-Root, last built 2024-05-07 against the 14.4 SDK); it needs SIP/Reduced Security and per-OS-version user approval, Apple is deprecating kexts, and the DriverKit replacement is a Hello-World stub. Whether it rebuilds/loads on macOS 27 with Xcode 27 is unverified.
  - Exclusive access: the user client admits one client per TPer (kIOReturnExclusiveAccess); a Haskell host and sedutil-cli (or the SED ToolBox daemon) cannot hold the same drive simultaneously. Root is required (kIOClientPrivilegeAdministrator).
  - Buffers handed to DriverPerformSCSICommand must be page-aligned (16 KiB on Apple Silicon) and the kernel copies exactly requestedTransferLength bytes; a Haskell FFI caller must allocate accordingly (sedutil uses IO_BUFFER_ALIGNMENT 16384).
  - Error fidelity on macOS is poor: sense data and SCSI status are dropped in DtaMacOS::PerformSCSICommand (everything collapses to 0xff), so the SAT sense[11] ATA-status check is vacuous and protocol-level failures are indistinguishable from transport failures.
  - DtaDevOpal::exec reads responses in 2048-byte TRUSTED_RECEIVEs (MIN_BUFFER_LENGTH) with a 25 ms busy poll and no timeout ('add timer --> advice from Joe'); large responses and slow bridges rely on outstandingData/minTransfer semantics being honored by the drive.
  - STACK_RESET is sent through session->sendCommand under security protocol 0x01 with a ComPacket header rather than as an IF-SEND protocol 0x02 STACK_RESET request; it should not be treated as a spec-conformant reference.
  - USB-bridge support depends on a hand-maintained 3-entry quirk table (RTL9210 attaches only via tryUnjustifiedLevel0Discovery because its IDENTIFY reports TCG Options = 0; Innostor IS888 is rejected; Sabrent needs timeout tweaks). Bridges not in the table may silently not attach to the kext, and then openDeviceHandle returns INVALID_HANDLE_VALUE.
  - ~/CLI.BrightPlaza is a stale 2023 snapshot tracked directly in the home repo and contains plaintext private keys/.p12 files not covered by git-crypt; it is not the tree the CI builds (that is sedutil/macos/CLI -> Customizations.OpenSource/macos/CLI).
  - Both DTA submodules are on detached HEADs; sedutil upstream is Drive-Trust-Alliance (GPLv3) while macos-driver is a private Bright Plaza repo. The kext's own copy of parseDiscovery0Features duplicates sedutil's and must be kept in sync by hand.
  - sedutil-cli links /Library/Frameworks/SEDKernelInterface.framework by absolute path and @rpath frameworks; building or running the CLI requires the installed framework version to stay ABI-compatible (installed cli was built against 603, frameworks now report 625).
