##### hsed-codec

SUMMARY:
hsed (/Users/scott/hsed, branch feature/types, Haskell/stack) contains a working, property-tested TCG token-stream codec and little else that executes. The codec is layered on one typeclass, StreamItem (attoparsec `parser` + `generate :: a -> ByteString`, with `pg = maybeParse . generate` as the canonical round-trip). Token.hs implements the full Table 04 token set (tiny/short/medium/long atoms as Unsigned Natural / Signed Integer / Bytes / ContinuedBytes, the four sequence tokens, five control tokens, Empty), rejects zero-length and TCG-reserved encodings with exact error strings, emits shortest encodings, and provides a conduit pipeline (tokenSource) that strips Empty atoms and joins continued byte sequences. Value.hs builds Datum/Name/NamedValue/List/Value on top; Call.hs builds MethodHeader/Parameters/MethodCall; UID.hs gives UID/HalfUID as refined fixed-size bytes (Core_bytes 8/4) whose StreamItem instances come via DerivingVia from a type-level BoundedSize/Refined library (src/Data/*) plus a large TH/quasiquote layer (TypeUIDs.hs is 3210 generated lines). Nothing above the method-call token level exists: no SubPacket/Packet/ComPacket headers, no session-manager methods, no IF-SEND/IF-RECV, no transport, no device model. TPer/Run.hs and Host/Run.hs are 12-line stubs that log one string; app/Main.hs parses only --verbose and runs the TPer stub. Table.hs is a placeholder with `TableRow ()` and `ColumnType ()`.

Testing: hspec-discover suite with TokenSpec (QuickCheck round-trips for every Token constructor, truncated/zero-length/reserved-tag error messages, Natural/Integer byte conversions), ValueSpec (only Datum round-trip; NamedValue/List/Value properties are commented out), and THSpec (pending). A doctest-discover target exists with ~91 `>>>` examples in the BoundedSize/Base_Type TH modules. Two codec defects are visible by reading against the spec text embedded in the same files: Call.hs omits the StartList/EndList that §3.2.4.2 requires around the parameter list, and Token.removeEmpty uses takeWhile, so an Empty atom terminates the stream instead of being ignored. Neither is caught because MethodCall has no round-trip test.

Build state is blocked twice before GHC version even matters. stack 2.11.1 (ghcup, aarch64) cannot download the Hackage index: `stack --no-install-ghc build --dry-run` fails with "root.json does not have enough signatures signed with the appropriate keys" (Hackage root keys rotated 2025-07-24; stack's changelog says 3.9.1 carries the new keyids). Separately, the resolver lts-17.7 pins GHC 8.10.4, for which ghcup reports no-bindist on aarch64-darwin; 8.10.5-8.10.7 do have bindists, 9.4.7 is installed at ~/.ghcup (HLS-powered), and /opt/homebrew/bin/ghc is 9.14.1. ~/.stack had never been used on this Mac (only a ghcup-delegating ghc-install hook); there is no .stack-work.

Porting to GHC 9.4 is moderate: the only singletons use is an empty `import Data.Singletons ()`, gdp/static-text/heredoc/regex-pcre-builtin/singletons 3.x are all in current Stackage, and roughly a third of package.yaml's dependencies (ghc, megaparsec, monad-loops, mtl, pretty, regex-pcre-builtin, static-text, transformers, vector, cborg, abnf) are never imported and can be dropped. Concrete source edits: three `PlainTV n` sites need the TH 2.17 flag argument, three modules import `Nat` from GHC.Base/GHC.Types (moved to GHC.TypeNats in 9.2), and the type-level `(<=)` constraints (now Assert-based) plus simplified subsumption with RankNTypes are the typecheck risk, concentrated in src/Data and the TH modules rather than in the codec. The cheapest route to a green build is lts-18.x (GHC 8.10.7, native aarch64) after upgrading stack; the 9.4 port is a second step.

RISKS:
  - Build is blocked before GHC matters: stack 2.11.1 cannot fetch the Hackage index (root.json signature failure from the 2025-07-24 Hackage root-key rotation); cabal 3.6.2.0 is from the same era and likely shares the problem.
  - lts-17.7 pins GHC 8.10.4, which has no aarch64-darwin bindist (ghcup: no-bindist); the ~/.stack ghc-install hook would hand that request to ghcup and fail, or Rosetta x86_64 would be needed.
  - Codec deviates from the spec in two places that a host/TPer pair would hit immediately: MethodCall omits the parameter-list StartList/EndList (Call.hs:210-212) and removeEmpty truncates the token stream at the first Empty atom (Token.hs:359-360); neither is under test.
  - Latent partiality: StreamItem [a]/(a,a) parser = undefined, `error` in combineContinued, long-atom bound allows lengths the 3-byte header cannot carry.
  - Everything the new program needs above tokens is greenfield: no ComPacket/Packet/SubPacket, no session manager, no method-response type, no transport abstraction, no device state; Table.hs is a stub.
  - The heaviest GHC 9.x porting surface (type-level BoundedSize/Refined, TH quasiquoters generating 3210-line TypeUIDs.hs, UndecidableInstances/RankNTypes, Assert-based (<=)) is also the least tested part (THSpec pending), so port regressions there would be silent.
  - package.yaml's single global dependency list makes the library depend on hspec/QuickCheck and on the unused `ghc` API package, which bloats and destabilises any new build plan (allow-newer: true is already papering over bounds).
  - abnf is an unmaintained git dependency (xldenis/abnf @ 2019 commit) that nothing in src imports; it still has to compile for every build.
  - Code has been idle since 2021-03; dev/script.save.* and script.gdptest show exploratory churn whose conclusions are not recorded anywhere but README.md 'Goals drift'.
  - Probe side effect: ~/.stack now holds config.yaml, pantry (with the abnf clone) and stack.sqlite3 (~804K); gitignored, no tracked file changed.
