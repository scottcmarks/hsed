# hsed spec-as-source

Design of record for annotating TCG Core 2.01 and Opal SSC 2.30 and compiling the annotated PDFs into a Haskell host jig and reference TPer. Synthesised 2026-10-25 from four candidate designs (fidelity, minimal, jig, delivery) and three judgements; revised the same day against three skeptic reviews (§14). Base: `minimal`.

Evidence: the survey maps and digest under `docs/evidence/2026-10-25/` (`maps/*.txt`, `digest.md`), the tag-tree extraction (`spec/ir/{core-2.01,opal-2.30}.json` produced by `tools/extract/extract_tables.py`; `docs/evidence/2026-10-25/extract/findings.md` and `regen_report.txt`), the M1 round-trip prototype, promoted to `tools/extract/{hsed_annot,annotate,apply,dump,pdf_checks}.py` (its report: `docs/evidence/2026-10-25/m1_report.md`), the skeptics' probes (`docs/evidence/2026-10-25/{classify,decode_di}.py`) and the lts-21.21 scratch build log (`docs/evidence/2026-10-25/lts2121-build.log`). Page numbers are PDF page indices unless marked "printed"; Core printed = PDF - 17, Opal printed = PDF - 1, Test Cases printed = PDF - 1.

## 1 Mandate and constraints

**Program.** Annotate the published PDFs of Core 2.01 and Opal 2.30 with PDF comments so they still read unchanged in an ordinary viewer, and compile the annotated PDFs into a running host (test jig) and simulated drive (reference TPer). Host and drive exchange a completely serialised command/response byte stream over pluggable transports: in-process; a real SED on a USB adapter through the BrightPlaza kext; two machines on the LAN through `~/mh_transport`.

**Hard constraint (Scott, verbatim).** "The pdf comments added to the original pdfs should be minimized and make use of Haskell definitions that allow them to say a lot with a little." Haskell is the target for minimalism and the possibility of proofs. Long-term wish: one source that renders as spec text, simulator and jig by switches.

**Direction of truth.** PDF -> IR -> code, never code -> PDF. hsed's hand transcription (TypeUIDs.hs, since M2d the oracle's test fixture `hsed/fixture/Hand/TypeUIDs.hs`) carries four wrong UIDs (Seconds all zeros; feedback_size, fraction_enum, gen_status with date's `18 04`) and two mis-numbered captions (157 as 147, 161 as 160); nothing may be bootstrapped from it. Regenerating it from the PDF and comparing at runtime is the first regression test.

## 3 Annotation language

### 3.1 Storage

```
<< /Type /Annot /Subtype /Text /F 6 /Rect [176.28 259.38 462.72 318.36]
   /Contents (erratum scott ["Fractoin" ~> "Fraction"])
   /HSED << /V 1 /Spec (core-2.01) /Id (T75) /Struct (0/1429) >> >>
```

- Flags `/F 6`. No `/Popup`, `/NM`, `/AP`, `/C` (pypdf emits a harmless `/Flags 0` beside `/F`).
- `/HSED` is identity only: schema version, spec, anchor id, struct path (`/K` index path, `0/1288` for Core T46). Ordinal, page and label, header, words hash, fragment Rects and caption are derivable from the pristine PDF, so they live in `spec/annot/<spec>.manifest.json` and are recomputed at `hsedc verify`; a table annotation stays near the 150-byte floor the M1 probe measured.
- One annotation per logical table, on its first fragment; the manifest lists fragments (Opal T38 spans PDF 56-78). The struct tree stitches a table's page fragments; Word's split tables (Core T7) stay two struct tables, which the IR records as parts 1 and 2 of one id and the annotation anchors on the first; repeated header rows are dropped by rule.
- Kinds: `/Doc` (one per PDF, also carrying document-wide `rule` tokens), `/Rule` (at a governing heading), `/Bind` (table), `/Law` (sentence or list item), `/Behaviour` (method heading or Fails list). Signature blocks are rule-bound and carry no annotation. A binding must be of its anchor's kind (`E-ANCHOR-KIND`): the doc anchor takes `doc <its own spec>` first, then rule tokens; a heading takes rule tokens or `behaviour`; a table takes a table binding or a bare modifier chain; a list item or paragraph takes `law`, `fails` or `behaviour`. One annotation per anchor; an id that names nothing in the IR is `E-ANCHOR`. A section whose payload starts with `behaviour`/`fails` is /Behaviour. The manifest carries `spec`, `source`, `md5`, `pages`, `labelOffset`, `anchors`, `irVersion` (*corrected, the M2c review:* not `rules` or `wordComplete`, which an earlier draft listed and no step reads: the rule tokens are the annotations', the word-complete sections the IR's, docs/ir-v1.md; reanchoring, M6, adds what it needs).

### 3.2 Anchor record and re-anchoring

Primary key: `(spec, Id)` where Id is `T<n>`, `<section>#<item>` (`3.3.10.2.1#3a`), `<section>/sig`, or `<section>`. Redundant keys in the manifest: struct ordinal and path, PDF page and printed label, normalised header, words hash, fragment Rects. `hsedc reanchor` matches by caption title (number stripped), then header, then words hash, then ordinal ±k, then geometry; Lost or Changed is an error, never a guess; a changed words hash on a `/Law` anchor blocks the build until the Law's quote is updated.

### 3.3 Grammar

```
payload  ::= binding | modifier+              -- a bare modifier chain applies to the table's rule default
binding  ::= name arg* | modifier binding | binding '&' binding   -- '&' joins independent bindings only (rule a & rule b)
modifier ::= name arg*                        -- erratum scott [...], rangeWords ["to"], cols 0 1, enumInDescription, as @'Shape, waive "C-UID-UNIQUE" "<subject>" "<reason>"
arg      ::= name | int | 0xHEX | "text" | (ref) | [arg, ...] | name ~> name
ref      ::= core int | opal int | § "dotted"
```

Names are the smart constructors of `Hsed.Spec.DSL` (§4.2). `hsedc bind` parses each payload with `Hsed.Spec.Grammar` (printer round-trip tested) and prints the same AST into `hsed-spec/bindings/Hsed/Bindings/<Spec>.hs`:

```haskell
{-# LINE 1 "core-2.01.pdf#page=107&T75" #-}
b_core_T75 :: Bound
b_core_T75 = at (anchor @'TypeRow "core-2.01" "T75") $ erratum scott ["Fractoin" ~> "Fraction"] typeRow
```

hsedc's grammar refuses unknown names and wrong kinds first, citing the page; `stack test hsed-spec:bindings` is GHC's check behind it (unknown names, modifier arity, a modifier of the wrong shape: "Couldn't match type 'EnumValues with 'TypeRow" at `core-2.01.pdf#page=…`). `hsedc check` adds `E-SHAPE`: the binding's semantic `Shape` must accept the table's measured `Form` (a `feature` comment on a three-column type table is an Error; `as @'Codes` on an odd form demotes it to a Warning with the page). Neither check links generated code into the library or `hsedc`.

### 3.4 Document-level rules

Headers are compared whitespace-stripped and case-insensitive after a typo table (`Colum Type`; `M axSize` and `MandatoryWrite  Granularity` differ only in whitespace, which the comparison strips), each use reported as `N-HEADER-NORMALISED`; grid corner cells are normalised before the byteGrid test (`Bit` + a lone `Byte` row in T17, `Bit Byte` in T18/T41-T44, `Byte\Bit` in T212; since M2c's scaffold each corner but T212's, which prints `Byte\Bit` itself, is read as `Byte\Bit` and reported as `N-HEADER-NORMALISED`, `Hsed.Spec.Shape.gridCornerNormalisation`, ten Notes in Core); rules see the extractor's `header_source` (§5.1). Scope comes only from the anchors: a `rule` token on a heading governs its subtree, on the `doc` annotation the whole document, several anchors union, so a rule binds only where an anchor scopes it (C-RULE-ANCHORED holds by construction and is not a separate check). Precedence: a rule may declare `refines <rule>` (`feature` refines `byteGrid`, `columnsAddition` refines `tableDesc`) and wins where both fire; any other double match is `E-AMBIGUOUS`; a full binding in a comment wins over every rule (Core T3, the `Foo Table Description` example, stays `prose` under the doc-wide `tableDesc`). A rule rides on the doc anchor wherever its shape (`Hsed.Spec.Shape.shapeMismatch`, held to its tables by `VocabularySpec`) picks out its tables across the document, save tables a comment binds anyway (§13.24); a heading anchor scopes it otherwise. `checkExemplars` re-verifies each exemplar's header on every run.

### 5.1 Stage A: extract (Python, `tools/extract/extract_tables.py`, run with `-I`)

### 5.2 Stage B: compile (Haskell, `hsedc`)

- `hsedc bind spec/ir/*.json` -> `hsed-spec/bindings/Hsed/Bindings/<Spec>.hs` (one `at (anchor @'S …) $ <payload>` per annotation with a LINE pragma). `stack test hsed-spec:bindings` type-checks every comment without touching the library or `hsedc`.
- `hsedc check`: classification (E-UNBOUND, E-AMBIGUOUS), `accepts` (E-SHAPE), rules, every rule's checks (its `RuleDef`, M2a), `checkExemplars`, anchor kinds (E-ANCHOR, E-ANCHOR-KIND), law hashes, the Format corpus; per-table ledger; non-zero exit on Error. `bind` and `compile` write nothing on an Error; every command (`orphans`, `ledger`, `explain` included) exits non-zero on one.
- `hsedc compile --errata scott --target core --target opal230 -o gen/ --report build/report/` builds CoreModel, applies the Opal patch list in document order, emits `gen/**/*.hs` with provenance Haddocks (and removes every other module of the spec's directory, `gen/Hsed/Gen/<Spec>/`, so that a module no rule emits any more leaves the tree), `gen/Hsed/Gen/Bindings.hs`, `build/report/{findings,coverage,ERRATA,ledger}.md` (M2b): `findings.md` the counts by code, then every finding; `coverage.md` every numbered table with its section, every signature block in document order and every anchor with what it binds; `ERRATA.md` the list to send to TCG: the corrections the `erratum scott` annotations carry (table, PDF and printed page, as printed, corrected, annotation) with what each reports under both sets, then the run's findings by what their code reports (`Hsed.Spec.Report.catalogue`): defects of the PDF, text read other than as printed, what is worth a look, each at its PDF page with the printed page beside it, and a code the catalogue does not name under "Not yet classified", so a new rule's findings are never dropped (on the committed run there is none, `ReportSpec`). The ledger (tables per binding and per rule, findings per code) is committed as `docs/LEDGER.md` by `make gen`: the totals live there, and the tests hold invariants. `--target doc` renders bound tables as Markdown with page citations.
- `hsedc gen` = extract -> bind -> check -> compile in one invocation; the pre-commit hook runs it and refuses a commit that changes `spec/ir`, `hsed-spec/bindings` or `gen/` without the corresponding source change. `stack build hsed` then runs the binding-check splice.

### 5.3 Annotation round trip

- `spec/annot/<spec>.hsa`: one line per anchor, `core-2.01 | T75 | erratum scott ["Fractoin" ~> "Fraction"]`; page, Rect, ordinal and hashes are never hand-typed.
- `hsedc annotate` (M1: `tools/extract/annotate.py`, pypdf `PdfWriter(path, incremental=True).add_annotation`, deterministic) writes `build/<spec>.hsed.pdf` as pristine + ONE incremental section with annots sorted by key and exports `spec/annot/<spec>.upd` and `<spec>.manifest.json`. No separate `squash`. `hsedc apply tcg/<pdf> <spec>.upd` verifies md5 and concatenates; `hsedc dump` recovers the `.hsa`.
- `hsedc adopt`: a visible sticky note typed in a viewer (a `/Text` without `/HSED`) is hit-tested by Rect against the page's table Rects, rewritten as a hidden anchored annotation in a fresh incremental section, and its text parsed as a payload; a note hitting no table or failing to parse is reported with its page. ## 6 Wire contract

### 6.1 Haskell interface (`Hsed.Wire`)

```haskell
data Dir = IfSend | IfRecv
data Request = Request { dir :: Dir, proto :: Word8, comId :: Word16, lenBytes :: Word32 {-IF-SEND payload / IF-RECV allocation-}, payload :: ByteString }
data IfStatus = Good | InvalidSecurityProtocolId | InvalidTransferLengthOnIfSend | OtherInvalidCommandParameter
              | SynchronousProtocolViolation | DataProtectionError | TransportFailure Text {-kext kIOReturn, socket loss-} | Unsupported Text
data Response = Response { status :: IfStatus, rpayload :: ByteString }  -- IF-RECV: exactly lenBytes bytes, zero-padded
data Event = PowerCycle | HardwareReset | HotPlug   -- Opal Table 16 types 0-2; Programmatic (3) is TPER_RESET, an IF-SEND
data Unit = UnitBlocks512 | UnitBytes;  data Cap = ReadOnly | ReadWrite   -- not Bytes: Hsed.Core.Layout's and Token's constructor (M3)
data Describe = Describe { dRole, dImpl :: Text, dUnits :: Unit, dSsc :: Maybe Text, dBaseComId, dNComIds :: Maybe Word16, dDevice :: Maybe Text }
data Transport (c :: Cap)   -- abstract (M3): its constructor is Hsed.Wire.Internal's, `type role Transport nominal`, seen only by
  -- Hsed.Wire, Hsed.Transport.*, Hsed.Jig.Guard and Hsed.Jig.Transcript: MkTransport { tExchange :: Request -> IO Response,
  -- tInject :: Event -> IO IfStatus, tUnit :: Unit, tDescribe :: Describe, tClose :: IO () }
ifRecv :: Transport c -> Word8 -> Word16 -> Word32 -> IO Response
ifSend :: Transport 'ReadWrite -> Word8 -> Word16 -> Word32 -> ByteString -> IO Response   -- the payload zero-padded to the length
inject :: Transport 'ReadWrite -> Event -> IO IfStatus
unitOf :: Transport c -> Unit;  describeTransport :: Transport c -> Describe;  closeTransport :: Transport c -> IO ()   -- hspec has a describe
newtype Channel = Channel (IORef (Map Word16 (MVar ())))
withComId :: Channel -> Word16 -> IO a -> IO a       -- one command in flight per ComID; a second IF-SEND queues, never issues
transferLength :: Unit -> Int -> Word32              -- `blocks 1` = 512 on UnitBlocks512, 1 on UnitBytes (SPF-02 case 2)
roundUp :: Unit -> Word32 -> Word32;  unitsFor :: Unit -> Word32 -> Word32 -> Either IfStatus Word32   -- 0 or over the most: refused
data ExchangeOpts = ExchangeOpts { xRecvLen :: Word32, xPollMicros, xTimeoutMicros :: Int }   -- defaultExchangeOpts 2048, 25 ms, 10 s
data ExchangeError = IfError IfStatus | Malformed Text | TimedOut | Refused Text
exchangeComPacket :: ExchangeOpts -> (Request -> IO (Either Text Response)) -> Channel -> Transport c -> Word16 -> ByteString
                  -> IO (Either ExchangeError [PacketFrame])   -- the IF-SEND path a parameter: the transport's, or the Guard's for a drive
  -- IF-SEND, then IF-RECV (len = negotiated MaxComPacketSize, default 2048) while OutstandingData /= 0:
  --   Length 0 / OutstandingData 1 / MinTransfer 0 -> sleep 25 ms, retry;
  --   MinTransfer M /= 0, with or without data in this ComPacket -> re-issue with max M len (rounded to units);
  --   OutstandingData 0 -> done; per-request timeout 10 s (the kext's SED_TIMEOUT).
  -- Host half of Law "Sync.table45"; sedutil's `minTransfer == 0` stop (DtaDevOpal.cpp exec loop) drops Table 45 row 3 and is not copied.
```

*As built (M3):* `exchangeComPacket` holds the ComID's lock throughout; its IF-SEND goes through the function passed in, the ComPacket zero-padded to whole units, and IF-RECV starts at `roundUp xRecvLen`; MinTransfer M not 0 (Table 45 rows 2 and 3) asks again at once at `roundUp (max M len)`; OutstandingData 0 (rows 5 and 6) ends it, `Right []` for (0,0,0) with nothing returned; otherwise (rows 1 and 4) it sleeps `xPollMicros` and polls until `xTimeoutMicros` have passed since packets last arrived (`TimedOut`), each command bounded by the same timeout; *since the M3 review* the whole exchange is bounded as well, `TimedOut` past `xTotalMicros` (60 s) from its IF-SEND and `Malformed` past `xResponseBytes` (1 MiB) of packets collected, so that a TPer that keeps returning packets cannot hold the host. `Refused`: a length over what a transport carries (255 blocks; 1 MiB in bytes; `mostCarried`); `Malformed`: an answer that is no ComPacket of the ComID, one with extension 0xFFFF (an inactive ComID, §8.2), *since the M3 review* one whose extension is not the one its IF-SEND carried (the ComID in use elsewhere, Core 3.3.3.1), or a MinTransfer at or below the length asked with no packets (no row of Table 45); `IfError`: any status but Good. `transferLength` saturates at the largest whole-unit length 32 bits hold, as `roundUp` does, rather than wrapping. *Since the M3 review* the contract's constants are defined once, in `Hsed.Wire`, and every module takes them from there: `comPacketProtocol` (0x01), `level0ComId` (Core Table 26's row, read from the generated table), `dataKind` (Table 19's), `staticExtension` (0x0000), `inactiveExtension` (0xFFFF), `comPacketHeaderSize` and `mostCarried`; the property names the simulator and the jig read are `Hsed.Sim.Types`', held to Core Table 167's generated names by a test (§13.29 (g)). Because `withComId` queues a second IF-SEND, ETC-02 sends through the jig's raw verbs (`rawIfSend`, `ifRecvOn`), which bypass the Channel (§9.1). The loop's clock is `GHC.Clock`'s: RIO's `getMonotonicTime` (unliftio 0.2.25) was measured returning nanoseconds on this Apple-silicon Mac (1.02e8 for a 100 ms sleep).

### 6.2 Units and padding per transport

| transport | unit | IF-SEND | IF-RECV | protocol 0x02 |
|---|---|---|---|---|
| SCSI A2h/B5h | UnitBlocks512, INC_512=1 | round up to 512, zero pad | allocation in whole blocks | one block |
| SAT A1h wrapping 5Ch/5Eh | UnitBlocks512 | count = ceil(len/512), 1 to 255 | count = ceil(len/512), 1 to 255; the kext's requestedTransferLength is count*512 exactly (`TPerDriver.cpp:273`, `CDBAccess.cpp:46-50`) | one block |
| NVMe Security Send/Receive | Bytes | as is | as is | bytes |
| mh_transport, in-process | UnitBytes | as is; simulator ignores bytes beyond ComPacket.Length | zero-padded to len | as is |

The simulator with `--units blocks512` rejects a non-multiple with OtherInvalidCommandParameter (SIIS §4.3); with `--units bytes` an IF-RECV shorter than the 20-byte header is "insufficient transfer length" per Table 45, not an error. Interface status is never carried in payload. On the kext path an error is the raw `kern_return_t`, carried in `TransportFailure` (*corrected (M3):* the `0xff` was sedutil's, `DtaMacOS.cpp:416-421`); interface statuses stay unobservable there, no sense data being returned, and the jig records expected-status assertions as "unobservable on this transport".

### 6.3 mh_transport frames (SPEC v1 unchanged; JSON text frames; reply on the originating socket, no `seq`)

```json
{"type":"hello","v":1,"server_id":"q7d2m0s8x1kz","seq":0,"heartbeat":{"interval_ms":20000,"timeout_ms":60000},
 "app":{"sed":{"v":1,"role":"tper","impl":"hsed-sim 0.1.0","units":"bytes","ssc":"opal-2.30","errata":"scott","base_comid":4100,"n_comids":1}}}
{"type":"sed.req","id":2,"op":"if_send","proto":1,"comid":4100,"len":2048,"payload":"AAAAABAEAAAAAAAAAAAAAFQ…"}
{"type":"sed.rsp","id":2,"status":"good","len":0}
{"type":"sed.req","id":3,"op":"if_recv","proto":1,"comid":4100,"len":2048}
{"type":"sed.rsp","id":3,"status":"good","len":2048,"payload":"AAAAABAE…"}
{"type":"sed.rsp","id":4,"status":"synchronous_protocol_violation","len":0}
{"type":"sed.evt","seq":7,"event":"power_cycle","comids_reset":[4100],"sessions_aborted":[[4100,4096]]}
```

- `op` ∈ `if_send | if_recv | reset | describe`. `status` is the snake_case of `IfStatus` plus `protocol_error`, sent only in reply to a frame whose `type` is `sed.req` (bad fields, non-increasing id, len > 1 MiB). Every other frame (unknown type, non-JSON, binary) is ignored with no reply, as SPEC.md L18-21 requires and conformance check 3 tests.
- Ids are positive and strictly increasing per socket. The client subscribes before sending, correlates by id, times out per request, fails all pending on disconnect or on a hello with a new `server_id` (treated as PowerCycle). IF-RECV may be retried after reconnect; IF-SEND is never replayed blindly.
- The hub processes `sed.req` in arrival order per socket; the per-ComID S1/S2/S3 machine is shared across sockets, so two hosts on one ComID legitimately see `synchronous_protocol_violation`. `sed.evt` is a seq-stamped broadcast (SPEC.md L9-14, L35-53) for resets injected by any client or the operator. Optional `?token=` pre-hello check beyond localhost.

## 12 Risks
